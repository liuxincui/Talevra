# RealCash 网赚接入开发计划

目标：在无登录、无真实提现入口的前提下，完成匿名设备网赚最小闭环。本文按依赖顺序执行，接口协议见 [realcash-api-spec.md](realcash-api-spec.md)。

## 阶段 0：运营与服务端前置

- 提供测试/正式 Base URL、`productId`、接口版本。
- 通过安全渠道提供 `privateKey`、`iv`；密钥只放服务端，不进客户端和 Git。
- 确认广告平台、`slotId`、`unitId`、`slotType`、`ad_platform`。
- 确认国家配置是否只单独配置新人奖励，其他数值是否全球统一。
- 确认任务接口返回的最终 `taskCode/taskId` 样例。

交付物：运营配置表、接口联调账号/设备、测试环境可用响应。

## 阶段 1：匿名设备身份

- 首次安装生成稳定 `deviceId`，持久化到本地安全存储。
- 调用 `user/reportInfo`，保存 `haloUid` 和 `resTime`。
- 启动、后台恢复时校验本地身份完整性；身份缺失时重新初始化。

验收：同一设备重启不变更 `haloUid`；清除应用数据后按新设备处理。

## 阶段 2：网络层与签名

- 封装统一 POST 客户端、超时、重试和错误解析。
- 在服务端实现签名，按原始 JSON 字节计算 Token。
- 记录 `RequestTime`、请求 ID、HTTP 状态和 RealCash `status`，敏感字段脱敏。

验收：测试环境所有接口签名通过；客户端包内搜索不到 `privateKey/iv`。

## 阶段 3：配置中心

- 接入 `app/configCenter`，按 `productId + country + version` 缓存。
- 将 RealCash 配置映射到本地 `EarningConfig`，未返回字段不覆盖已有缓存。
- 对数组配置做长度校验：目标数组和奖励数组长度必须一致。

验收：启动后能展示运营表中的看剧、看广告、签到和频控数值；切换国家只改变已配置的国家差异项。

## 阶段 4：任务读取、执行和领取

- 接入 `task/all`，保存任务模板和用户进度。
- 看完一集调用 `task/do`，用剧集/集数生成幂等键。
- 签到调用 `task/do` 的登录任务。
- 用户点击领取调用 `task/collect`，成功后刷新任务和余额。
- `childrenRound`、`nowRound` 按原字段处理，不在客户端自行推导周期。

验收：重复观看同一集、重复签到、重复领取均不重复发奖；重启后进度一致。

## 阶段 5：广告事件与金币结算

- 对每次广告生成 `reqId`，按 SDK 生命周期上报 `eventInfo`。
- 激励广告完成后上报 `videoCompleted`，再调用 `getCoins`。
- `getCoins` 使用唯一 `cid`；成功以 `totalCoins` 覆盖本地余额。
- `adEventSource=4` 场景不调用 `getCoins`，避免重复发币。

验收：广告完成一次只到账一次；插屏只计事件不误发激励奖励；频控达到后不再自动重试。

## 阶段 6：异常、风控和离线降级

- 所有写接口实现幂等重试和请求去重。
- 网络失败不本地补发金币；配置使用最近一次成功缓存。
- 服务端返回频控/风控错误时停止当前奖励动作并刷新余额。
- 对设备号、IP、广告频次和每日收益限制保留服务端结果，不信任客户端计数。

验收：断网、超时、重复回调、切后台恢复和系统时间异常均不会重复发币。

## 阶段 7：联调与发布验收

- 按 US、BR、ID、KR 和 default 五组配置各跑一遍。
- 验证新人奖励只发放一次；任务梯度、广告收益换算和签到数组逐项核对。
- 验证正式环境域名、证书、签名密钥和日志脱敏。
- 记录接口版本、运营配置版本、客户端版本和测试设备号。

## 明确不做

- 不接 `level/list`、`order/create`、`order/list`，因为当前没有提现入口。
- 不接 `module/*` 互动组件，不接 `strategy/info`。
- 不在客户端实现提现、兑换或本地余额账本。

## 开发完成定义

用户无需登录即可完成：首次初始化、看到任务、看剧推进、签到、看广告上报、广告金币结算、领取任务奖励，并在重启后保持设备身份和服务端余额一致。
